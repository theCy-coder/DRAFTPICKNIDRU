1. How to simulate a broadcast (recommended)

The tool has two halves: the control panel the operator clicks, and the overlays the audience sees. A test only counts if the tester watches the overlay change, not just the control panel. The recommended arrangement:

  • Two screens, or one screen split in half. Left: the control panel. Right: the overlay under test.
  • Best: use OBS. Add each overlay as a Browser source at 1920 × 1080 (links are in Settings → OBS links), one scene per overlay, and watch OBS’s preview. This is the real environment and catches transparency and performance problems a browser tab hides.
  • Acceptable: browser tabs. Open each overlay in its own tab or window. It shows a dark backdrop instead of transparency; everything else behaves the same.
  • Play a real match alongside. For the Live game cases, run an MLBB replay or spectate a match, and press the buttons as events happen. Timing mistakes and awkward button placement only show up under real pressure.
  • Test as a rehearsal, in show order. Sections 5–11 follow one series from start to finish. Run them in order with the same data instead of resetting between cases; section 16 is the same flow as a single script.
  • Record the session (OBS recording is enough). When something looks wrong, the recording shows exactly which press caused it.
Never test on show data. Everything the panel changes is saved straight to data/state.json. Back that file up first (section 2), and restore it when testing is finished.

2. Setup before testing

  1. Close the server window if it is open. Copy data/state.json to data/state.backup.json.
  2. Double-click MLBB Overlay Server.exe (or Start Overlay Server.bat). Leave the window open.
  3. Open http://localhost:8777/control.html in Chrome, Edge or Opera.
  4. Load the test season: Season → Save / load → Import and choose season-finals.json from the project folder. It contains 6 teams, 30 players, 18 scheduled matches (17 played, the Grand Final still to play), a bracket and hero records from 47 games.
  5. Open the overlays you will watch: draft.html, scoreboard.html, mvp.html, idle.html, loading.html.
  6. After testing: close the server, copy state.backup.json back over state.json, start the server again.

Reloading a page (F5) never loses match data; it is all stored on the server.

Destructive buttons (Reset draft, Reset series, Clear played heroes, Clear season, Clear hero records) need a second click within 3 seconds. Check both the confirm and the “do nothing and let it time out” path once.

16. Full rehearsal script

One pass through a best-of-3 as the operator would run it on show day. Use it as the final sign-off after the individual cases pass.

  1. Before the show. Season → Save / load → Import the season. Settings → Look → pick the show design. Setup → Scheduled match → today’s match. Set Series to Best of 3.
  2. Pre-show. OBS scene: Waiting. Setup → Waiting screen → Minutes 2 → Start. Confirm the rotation and ticker run and the last 10 seconds return to the matchup.
  3. Draft. OBS scene: Draft. Draft pill ON. Press Space to start the timer. Enter every ban and pick as called. Fix one deliberate mistake using a slot click and Undo.
  4. Loading. OBS scene: Loading. Leave it for one full rotation. Check all ten heroes, the three card faces and five centre slides.
  5. Game 1. OBS scene: game + Scoreboard. Scoreboard pill ON. Use only hotkeys for announcements while a real match or replay plays.
  6. Post-game. Step 1: click the MVP’s hero and type the stats. MVP pill ON; OBS scene: MVP. Step 2: press who won. Confirm the panel moves to the Draft tab and game is 2.
  7. Game 2. Repeat steps 3–6. In fearless mode confirm game 1’s heroes are locked.
  8. Series end. After the deciding win confirm “Series over … Saved to the season schedule.”, then check Season → Schedule and Standings.
  9. Wrap. Season → Save / load → Export, and keep the file.

17. Known limits (not bugs)

  • Draft comparison bars are estimates. The six ratings on the loading screen come from each hero’s class, not from game data, so two heroes of the same class score the same. Only “Draft win rate” is real season data. Per-hero corrections go in js/hero-ratings.js.
  • No counter index. There is no data on which heroes counter which.
  • Hotkeys need the control panel focused. They do not work while another program (the game, OBS) has the keyboard.
  • Only the “who won” buttons write a result to the schedule. The small − / + score corrections do not.
  • The playoff rule is by pairing. A scheduled match is treated as a playoff when its two teams also appear together in the Bracket (taking that pairing’s latest match).
  • Undo after a draft action only rewinds picks and bans; after a “who won” press it rewinds the whole game.
  • The loading screen’s card timing (6 seconds per face) is fixed.
  • Sample player photos in Assets/Players are AI-generated placeholders for testing, not real players.
Report a failure with: the case ID, the show design in use, the browser or OBS version, what you pressed, what you saw, and a screenshot or the recording time.
